# Spec: Welcome window

Date: 2026-11-11. Status: built. Design: `docs/design/DESIGN.md`, section "Welcome window".

## Goal
Someone who opens Macarum for the first time understands what it is, where it lives and why
macOS is about to ask for a permission, before macOS asks. Until now the first launch showed
the bare macOS Accessibility prompt with no explanation, which reads like an install warning.

## When it shows
- Once, on the first launch. Macarum remembers it under the setting `welcomed`, saved as soon
  as the window is shown.
- Not for people coming from a version before this window: those versions saved
  `askedAccessibility` after showing the macOS prompt at launch, and whoever has it set counts
  as welcomed. The setting is only read now.
- Again on request: Settings, last row, "Show Welcome".
- Macarum no longer asks for Accessibility at launch. The macOS prompt comes up only from the
  button in this window, from the "Allow…" row in Settings, or when an item is picked for
  pasting while the permission is missing (as before).

## What it says
One fixed window, 520 pt wide, no title text, centred, brought to the front (Macarum has no
Dock icon, so it activates itself).

- App icon, "Welcome to Macarum", "Three small tools that live in your menu bar."
- Find it in the menu bar: "Click the macaron at the top right. There is no Dock icon.", next
  to the menu bar glyph as it really looks.
- Clipboard history: "Press ⌘ three times to see what you copied and paste it again."
- Memory check: "See what is holding memory, and quit or relaunch it."
- File converter: "Drop images, PDFs, video or sound on the macaron to convert."
- One permission: Accessibility. "Pressing ⌘ three times and pasting for you both need it.
  macOS will ask in its own, rather stern words." Then what it is used for: "Macarum uses it to
  watch the modifier keys like ⌘, to notice that a key or mouse button was pressed (never which
  key), and to press ⌘V when you pick an item. Nothing leaves this Mac."

The permission text matches the code. `CommandTapMonitor` listens for modifier changes, key
downs and mouse downs in other apps. From a modifier change it keeps which modifiers are held
and when; from a key down or a mouse down it keeps only that one happened (to tell three ⌘
taps from ⌘C or a ⌘-click), never the key code or the characters. `Paster` posts ⌘V. Macarum
makes no network connections.

## The permission step
Three states, in `WelcomeFlow` (MacarumCore, unit tested):

| State | State line | Buttons |
|---|---|---|
| Explaining | "Not now is fine: Macarum still works from its menu bar icon." | Not Now, **Allow Accessibility…** |
| Waiting | spinner, "Waiting for you to switch Macarum on in System Settings…" | Not Now, **Open System Settings** |
| Granted | green check mark, "Accessibility is on. Press ⌘ three times to try it." | **Done** |

- "Allow Accessibility…" shows only the macOS prompt (its "Open System Settings" button leads to
  Privacy & Security > Accessibility and closes the prompt), as the row in Settings does, and
  moves to Waiting. Opening the pane at the same time left the prompt behind on screen after the
  switch was on (seen on the first real run, 2026-11-11). Once macOS has asked, the same buttons
  open the pane instead. "Open System Settings" only opens the pane
  again.
- While the window is open Macarum asks macOS once a second whether the permission is there.
  The check stops when the window closes.
- The permission arriving moves to Granted from either state (it can be switched on by hand),
  and the window comes back to the front so the result is seen. If the permission is already
  there when the window opens, it starts at Granted. If it is taken away while the window is
  open, the window goes back to where it was.
- Once granted, the first sentence of the permission text changes to "Pressing ⌘ three times
  and pasting for you both use it. You can switch it off in System Settings at any time."
- "Not Now", Esc and the close button all just close the window. Nothing is lost: the history
  opens from the menu bar icon, pasting is ⌘V by hand, and Settings keeps its warning row with
  "Allow…".
- The window is the same size in every state.

## Preview
`-MacarumPreviewWelcome YES` shows only this window: no menu bar icon, clipboard monitor,
history store or shortcuts, and macOS is never asked for anything (the buttons only change
what the window shows). `-MacarumPreviewWelcomeWaiting YES` starts in Waiting,
`-MacarumPreviewWelcomeGranted YES` in Granted, `-MacarumPreviewWelcomeGrantAfter 3` lets the
permission arrive after three seconds, `-MacarumPreviewIcon <path>` gives the app icon (a bare
binary has none), `-MacarumAppearance light|dark` picks the look.

## Checked (2026-11-11)
- Who sees it and the three states: 11 unit tests (`WelcomeTests`).
- The window in light and dark, in all three states, through the preview run; the same size
  in each. Waiting turning into Granted by the once-a-second check, through
  `-MacarumPreviewWelcomeGrantAfter`.
- The "Show Welcome" row in Settings: looked at, not clicked.
- Not yet: a real first launch of an installed copy (the window appearing on its own, in front,
  and the real macOS prompt and System Settings after the button), and the buttons pressed by
  hand.
